# Prompts

> 반복해서 쓰는 프롬프트 모음. `{ }` 부분만 바꿔서 붙여넣는다.
> 각 템플릿 제목 옆에 사용하는 곳을 표시했다. (Project = Claude Project, Code = Claude Code)
> 보내기 전에 `{ }` 자리표시가 남아 있지 않은지 확인한다.

## 작업 상태 블록

Project와 Code는 서로의 대화를 볼 수 없다. 그래서 아래 블록으로 현재 상태를 주고받는다.
템플릿 맨 위에 붙이고, Claude 답변 끝의 갱신된 블록을 복사해 다음 도구로 넘긴다.

```
[작업 상태]
- 이슈: #{번호} {제목}
- 브랜치: {브랜치명 또는 없음}
- 지금 상태: {한 일 / 현재 위치}
- 막힌 점: {없음 또는 오류 요약}
- 다음 할 일: {한 줄}
- 수정 제안 대기: {없음 또는 목록}
```

---

## 1. 이슈 시작 · Project

```
{작업 상태 블록}

이슈 #{번호}를 시작한다. 이슈 내용은 아래와 같다.
{이슈 본문 붙여넣기}

1) 이 작업에서 알아야 할 개념과 주의할 점
2) 진행 순서
를 알려주고, 끝에 작업 상태 블록을 갱신해줘.
```

## 2. 작업 실행 · Code

```
{작업 상태 블록}

이슈 #{번호}용 브랜치 {브랜치명}에서 {할 일}을 진행해줘.
시스템 설정을 바꾸기 전에는 먼저 설명하고, 결과는 docs/{파일}에 기록해줘.
"다음 할 일"은 블록에 받은 계획 순서를 유지하고, 바꿀 필요가 있으면 제안으로만 적어줘.
끝나면 작업 상태 블록을 갱신해줘.
```

## 3. 막혔을 때 · Project

```
{작업 상태 블록}

{무엇을 하려다가} 아래 오류가 났다.
- 실행한 명령: {명령}
- 오류: {오류 메시지 붙여넣기}

원인과 해결 방법을 설명하고, 끝에 작업 상태 블록을 갱신해줘.
```

## 4. 기록 남기기 · Code

```
{작업 상태 블록}

아래 내용을 docs/{decisions.md | env.md}에 기존 형식대로 짧게 추가해줘.
{기록할 결론}
```

## 5. 이슈 마무리 · Code

```
{작업 상태 블록}

수정 제안 대기 항목을 반영하고, docs/progress.md에서 이 이슈를 완료로 갱신해줘.
변경 사항을 커밋하고 push한 뒤 gh로 PR을 올려줘. (gh 인증, D-008)
이슈의 "결과 / 배운 점" 초안도 작성해줘. 내가 머지 전에 이슈에 붙여넣고 완료 기준을 체크한다.
PR 본문에는 무엇을·왜·어떻게 확인했는지와 `Closes #{번호}`를 넣어줘.
그다음 이 PR을 리뷰해서 고칠 점이 있으면 알려줘.
```

## 6. 개념 학습 · Project

```
현재 Phase: {Phase}
{개념}을 설명해줘. 이 프로젝트(CARLA + Autoware)에서 어디에 쓰이는지와,
직접 확인해볼 수 있는 간단한 실습도 함께 알려줘.
```

## 7. 회고 · Project → Code

목표(Phase) 달성 시, 또는 한 목표에 1주 이상 진전이 없을 때 한다.

```
[Project]
{목표 달성 | 진전 없음 점검} 회고를 하자.
- 대상 목표: {Phase 또는 이슈 묶음}
- 끝낸 이슈: {#번호들}
- 진행 중 / 막힌 점: {내용}

1) 잘된 점과 개선할 점
2) progress.md 갱신 내용
3) 다음 목표 (이슈 단위). 진전이 없었다면 원인과 범위 조정안
을 정리해줘.
```

```
[Code]
아래 회고 내용으로 docs/progress.md와 docs/devlog/{YYYY-MM-DD}_{주제}.md를 갱신하고 PR을 올려줘.
Phase 마지막 정리 이슈에서 만든 devlog가 있으면 새로 만들지 말고 그 파일에 회고 섹션을 추가해줘.
{Project 회고 결과 붙여넣기}
```

## 8. Phase 전환 · Project → Code

Project에서 완료 여부를 점검한 뒤, Code에서 태그와 Release를 만든다.

```
[Project]
Phase {N} 완료 여부를 점검하자. 완료 기준은 roadmap.md를 따른다.
- 끝낸 내용: {요약}

1) 완료 기준별 충족 여부
2) Release 노트 초안
3) 다음 Phase의 구체적인 완료 기준과 첫 이슈 목록
을 정리해줘.
```

```
[Code]
main에 v0.{N+1}.0 태그를 붙이고, 아래 노트로 GitHub Release를 만들어줘.
{Release 노트 붙여넣기}
```

## 9. 다음 이슈로 넘어가기 · Project

이슈 PR이 병합되면, 진행하던 채팅에서 요청한다. 받은 프롬프트로 새 채팅을 연다.

```
{작업 상태 블록}

이슈 #{번호}의 PR이 병합되어 마무리됐다. 다음 이슈는 #{다음 번호}다.
새 채팅에 붙여넣을 시작 프롬프트를 템플릿 1번 형식으로 작성해줘.
- 작업 상태 블록은 다음 이슈 기준으로 새로 채우기
- 이번 이슈에서 다음 이슈에 이어지는 내용(주의점, 미반영 수정 제안)은 "이전 이슈에서 이어지는 내용"으로 짧게 포함
- 이슈 본문 자리는 {이슈 본문 붙여넣기}로 비워두기
```
